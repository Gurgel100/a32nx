# FDR Analyzer

FlyByWire Simulations flight data recorder (FDR) viewer — a cross-platform GUI application for inspecting, graphing, and exporting flight simulation telemetry data.

## What It Does

- **Opens `.fdr` files** — native binary FDR format produced by the FlyByWire A32NX and A380X aircraft for MSFS
- **Opens `.csv` files** — CSV exports generated by the `fdr2csv` CLI tool
- **Plots multiple parameters** across shared time axes with real-time interactive charts
- **Zoom into any time range** using the bottom timeline scrubber (drag handles, mouse wheel, keyboard shortcuts)
- **Creates multiple independent graph panels**, each with its own set of plotted parameters
- **Exports selected data** as CSV files for further offline analysis

## Architecture

```
fdr-analyzer/
├── build.rs              # bindgen: generates Rust types from C++ RecordingDataTypes.h headers
├── a320_wrapper.hpp      # includes all A320 recording type headers
├── a380_wrapper.hpp      # includes all A380 recording type headers
└── src/
    ├── main.rs           # eframe entry point, viewport setup, CLI file-arg handling
    ├── app.rs            # top-level layout: file info bar, parameter sidebar, graph area, timeline
    ├── fdr_reader.rs     # FDR binary + CSV readers; column-major storage; time-index query layer
    ├── plot_panel.rs     # individual egui_plot graph panels with LTTB down-sampling
    ├── value_selector.rs # searchable parameter browser sidebar
    ├── parameter_tree.rs # hierarchical grouping of parameters by subsystem
    ├── timeline.rs       # horizontal time scrubber with zoom/pan/reset interactions
    ├── downsample.rs     # Largest-Triangle-Three-Buckets algorithm for rendering millions of points
    └── export.rs         # CSV export of the currently visible data
```

### Data Flow

1. On file open, the FDR binary is decompressed (gzip) or the CSV is parsed into **column-major** storage (`BTreeMap<String, Vec<f64>>`)
2. A **time index** (`Vec<f64>`) of simulation timestamps is extracted for O(log n) range queries
3. The user selects parameters from the sidebar — each click adds the parameter to a graph panel
4. On every frame, the visible time range drives a query against the column-major store; results are **down-sampled** with LTTB to at most ~2000 points per series before rendering

## Building

### Prerequisites

- **Rust 1.80+** (edition 2021)
- **C++ compiler** (clang or gcc ≥ C++20, needed by `bindgen` for header parsing at build time)
- On Linux: Wayland/X11 development libraries (`libwayland-dev`, `libxkbcommon-dev`, etc.)

### Build and Run

```bash
cd tools/fdr-analyzer

# Debug build (development)
cargo run --release

# Open a specific file at launch
cargo run --release -- /path/to/your_file.fdr
cargo run --release -- /path/to/your_export.csv
```

A release build is recommended — the binary is optimized with LTO + strip for faster FDR parsing.

## Usage

### Opening Files

- Drag-and-drop is not yet implemented; open via **CLI argument** or the "Open File" button on the welcome screen (status bar shows instructions)
- Aircraft type (A320 / A380) and record count are shown in the file info bar at the top

### Adding Parameters to Graphs

1. Use the **Parameters sidebar** on the right
2. Expand a subsystem group (Simulation, Attitude, Flight Dynamics, Position, Atmosphere, etc.)
3. Click any parameter name — it is added to the currently active graph panel with an auto-assigned color
4. Parameters can be toggled on/off and recolored in each panel's **Panel Settings** collapsible

### Zooming and Panning

The **timeline bar** at the bottom of the window shows the visible time window as a highlighted region:

| Action | Effect |
|---|---|
| Drag left/right edge handles | Narrow or widen the visible range |
| Drag the center of the selection | Pan within the full flight timeline |
| Mouse wheel while hovering | Zoom in/out centered on cursor position |
| Double-click anywhere | Reset to full-flight view |
| `-` key | Zoom out 1.5× around center |
| `=` key | Zoom in (0.67×) around center |

All graph panels share the same X-axis time range.

### Exporting Data

Open the **Export** collapsible in the right sidebar and click **Export CSV**. This writes all currently visible parameter series across all graph panels for the current zoom window to a `.csv` file next to the original file (e.g., `flight.fdr` → `flight.export.csv`).

## Supported Parameters

Currently exposed parameters cover the `BaseData` + `AircraftSpecificData` structs from the FDR recording types:

| Group | Example Parameters |
|---|---|
| **Simulation** | Time, Delta Time, Sim Rate |
| **Position** | Latitude, Longitude |
| **Attitude** | Pitch (Theta), Roll (Phi), Heading (Magnetic), Pitch/Roll/Yaw Rates |
| **Flight Dynamics** | IAS, TAS, Ground Speed, Mach, AoA, Sideslip, Pressure Altitude, Vertical Acceleration |
| **Atmosphere** | Ambient Pressure |

Additional parameters from ELAC/SEC/FAC/FMGC computer telemetry can be added by extending `build_a320_params()` / `build_a380_params()` in `fdr_reader.rs` with the correct byte offsets.

## Tech Stack

| Component | Crate(s) |
|---|---|
| GUI framework | `egui` + `eframe` (v0.31) — cross-platform, immediate-mode |
| Plotting | `egui_plot` (v0.31) — line charts with zoom, pan, hover tooltips |
| Binary FDR decoding | `flate2` (gzip), `bytemuck` (zero-copy byte → struct) |
| CSV I/O | `csv`, `serde` |
| Build-time bindings | `bindgen` generates Rust types from C++ `RecordingDataTypes.h` |

## Limitations and Future Work

- **File open dialog** — currently CLI-only; a native file picker via `rfd` (rust-native-dialogs) is planned
- **More parameters** — only BaseData-level fields are wired up today; the computer telemetry structs (ELAC, SEC, FAC, FMGC, FADEC for A320; PRIM, SEC, PR/THR for A380) can be added with correct byte offsets
- **Drag-and-drop** — opening files by dragging onto the window is not yet implemented
- **Large-file streaming** — currently the full decompressed file is held in RAM; block-level decompression could reduce peak memory for multi-GB FDR recordings
